# 用户指南

PocketTally 是一款轻量、私有的个人记账应用。账本数据保存在你自己的 SQLite 数据库中。本文按当前主线的单所有者登录流程编写；当前公开的 `v0.1.0` 镜像尚不包含登录功能，版本部署差异见[部署与备份](deployment.md)。

> [!IMPORTANT]
> 这是单所有者账本，不提供公开注册、团队协作或多用户隔离。生产环境必须通过 HTTPS 反向代理发布，并配置 `POCKET_TALLY_PUBLIC_ORIGIN`；不要直接把 FastAPI 服务暴露到公网。

## 开始使用

### 1. 启动服务

从当前主线源码构建并部署时，先配置好 HTTPS 反向代理，在 `.env` 中设置浏览器实际访问的精确 HTTPS Origin，然后准备 `data/` 和 `backups/` 目录并启动：

```bash
docker compose up -d --build
```

通过反向代理提供的 HTTPS 地址打开应用。生产配置必须设置 `POCKET_TALLY_PUBLIC_ORIGIN=https://<实际域名>`，FastAPI 只允许在 Compose 网络内访问。`v0.1.0` 镜像不支持本文的登录流程，也不能通过 HTTPS 反向代理开放公网；其本机或可信内网使用方式见[部署指南](deployment.md)。

### 2. 初始化唯一所有者并登录

首次启动且鉴权库为空时，在后端容器中创建唯一所有者：

```bash
docker compose run --rm backend pocket-tally-auth init --username owner
```

命令会提示设置密码。随后打开 PocketTally 登录页；当前版本没有公开注册入口，只有初始化的所有者可以登录。右上角菜单可退出登录，会话默认有空闲和绝对时限。

认证、会话、CSRF 和密码恢复命令见[认证与会话](authentication.md)。

### 3. 创建账户并录入现有余额

第一次进入空账本时，先在“账户”页面创建现金、银行卡或其他账户。新账户初始余额为 0；如果你已经有实际余额，请使用“调账”录入，而不是补造一笔历史收入：

1. 点击“记一笔”，选择“调账”。
2. 选择账户和增加或减少方向，填写当前差额。
3. 按需要填写发生时间和说明，然后保存。

完成后，仪表盘中的账户余额应与现实余额一致。

### 4. 检查分类和标签

系统会预置常用的收入和支出分类。你可以在“分类”页面新增、编辑、移动或删除未被交易引用的分类；标签是可选的，适合标记项目、成员或场景等跨分类信息。

## 记录第一笔交易

点击右上角“记一笔”，根据业务选择类型：

| 类型 | 适用场景 | 必填重点 |
| --- | --- | --- |
| 收入 | 工资、奖金或其他入账 | 收款账户、收入分类、正数金额 |
| 支出 | 消费或付款 | 支出账户、支出分类、正数金额 |
| 转账 | 两个账户之间移动余额 | 转出账户、转入账户，且不能是同一账户 |
| 调账 | 让账面余额回到现实余额 | 账户、增加或减少方向；不需要分类 |

每笔普通交易都可以设置发生时间、说明和标签。金额使用人民币正数填写；收入、支出和转账的账户余额会在保存后更新。

## 日常使用

### 查询和统计

- “交易”页面可按说明、分类、账户或标签搜索，并按日期、类型和状态筛选。
- 点击交易行可查看详情并编辑有效交易。默认列表隐藏已作废交易，需要时切换到“全部状态”或“仅作废”。
- “统计”页面提供收支趋势、现金流、分类构成、标签和日历汇总；转账与调账不会被重复计入收入或支出统计。

### 修改、作废和退款

- 录入错误时优先编辑交易；如果交易不应再影响余额，使用“作废交易”。作废会保留记录和审计信息，但移除余额影响。
- 退款应从对应的支出详情中点击“申请退款”。系统会沿用原支出的账户和分类，并限制累计退款不能超过原支出；不要再把同一笔退款录成普通收入。
- 已产生退款关联的支出，部分字段会被锁定；通常仍可修改说明、发生时间和标签。

金额、时间、账户余额和统计口径见[业务规则](business-rules.md)。

## 备份、恢复和密码维护

在保存真实数据前、升级镜像前以及进行高风险操作前，都应创建并校验账本备份：

```bash
docker compose run --rm backup create
docker compose run --rm backup verify <备份文件>
```

账本库与鉴权库是独立文件：账本备份不包含登录凭据和会话数据。请按照[部署指南](deployment.md)分别制定主机级加密备份策略；需要重置密码、撤销会话或查看鉴权状态时，使用[认证与会话](authentication.md)中的 CLI 命令。

## 使用边界

- 当前版本面向单所有者，不支持公开注册、多用户隔离、团队协作或 MFA。
- 生产发布需要 HTTPS、正确的 `POCKET_TALLY_PUBLIC_ORIGIN` 和反向代理；本机开发可使用默认的 HTTP 地址。
- 不要直接修改 SQLite 文件。涉及余额、分类和关联记录的变更应通过应用界面或受支持的 CLI 完成。
- [v0.1.0 发行说明](releases/v0.1.0.md)记录的是历史发布基线，其中关于“无登录”的描述不代表当前主线。
