# 个人账单导入

## 当前交付边界

本轮先交付支付宝 CSV、微信 CSV/XLSX 的人工分类导入闭环。退款识别后跳过，自动关联退款及 AI 分类建议属于后续范围。ZIP、XLS、PDF 与商家账单不受支持。

## Schema 升级与恢复

账本使用 Alembic 顺序迁移；`0001` 是冻结的已发布账本结构，`0002` 增加导入审计模型。新库通过版本脚本建库，已有 v0.1/v0.2 库必须通过完整列、主键、外键、唯一与 CHECK 结构识别，未知结构拒绝升级。鉴权库仍独立管理。

启动时在 SQLite 写锁内升级，升级前使用现有在线备份 API 创建 `migration-backups` 一致性备份。迁移失败回滚并停止启动，保留原数据和备份。不要使用旧镜像直接启动新版数据库；需要回滚时先停止服务，再按部署文档恢复升级前备份。升级成功后重复启动不会重复备份或补种分类。

候选行不占用来源唯一键；只有提交成功的 `provider + source_id` 占用去重键。作废交易仍保留占用，重传不能恢复它的余额影响。账户映射随未引用账户删除失效；草稿账户和分类引用置空并重新校验。

批量记账与单笔记账共用完整状态校验和余额规则，在一个事务中写入全部交易，然后一次计算受影响账户的最终余额。借记账户最终余额不得为负，不要求历史逐时点余额非负。
