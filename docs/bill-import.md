# 个人账单导入

## 当前交付边界

本轮先交付支付宝 CSV、微信 CSV/XLSX 的人工分类导入闭环。退款识别后跳过，自动关联退款及 AI 分类建议属于后续范围。ZIP、XLS、PDF 与商家账单不受支持。

## Schema 升级与恢复

账本使用 Alembic 顺序迁移；`0001` 是冻结的已发布账本结构，`0002` 增加导入审计模型。新库通过版本脚本建库，已有 v0.1/v0.2 库必须通过完整列、主键、外键、唯一与 CHECK 结构识别，未知结构拒绝升级。鉴权库仍独立管理。

启动时在 SQLite 写锁内升级，升级前使用现有在线备份 API 创建 `migration-backups` 一致性备份。迁移失败回滚并停止启动，保留原数据和备份。不要使用旧镜像直接启动新版数据库；需要回滚时先停止服务，再按部署文档恢复升级前备份。升级成功后重复启动不会重复备份或补种分类。

候选行不占用来源唯一键；只有提交成功的 `provider + source_id` 占用去重键。作废交易仍保留占用，重传不能恢复它的余额影响。账户映射随未引用账户删除失效；草稿账户和分类引用置空并重新校验。

批量记账与单笔记账共用完整状态校验和余额规则，在一个事务中写入全部交易，然后一次计算受影响账户的最终余额。借记账户最终余额不得为负，不要求历史逐时点余额非负。

## 文件解析

按内容识别支付宝 CSV、微信 CSV/XLSX；支持 UTF-8/GBK、引号和银行卡尾号，平台无时区时间按上海时间转换成 UTC。金额直接从十进制文本转换为整数分，不经过浮点。

退款行单独识别；原支出上的“已全额退款”等状态仍是原支出，不能误当成退款行。退款和零金额记录明确排除。相同来源单号的可入账明细完全一致时折叠，内容冲突时两行均不支持；退款与原支出共用来源单号不构成此类冲突。

单文件最多 10 MiB、10,000 个交易数据行，XLSX 解压内容最多 100 MiB；拒绝损坏、加密、宏和公式单元格。CSV 公式形式的字段标为不支持，不执行或信任。

本地真实格式核对：支付宝 771 行（599 个普通候选、35 个退款、134 个跳过、3 个不支持）；微信 169 行（164 个普通候选、4 个退款、1 个跳过）。支付宝导出摘要的支出额采用扣除退款后的口径；逐行支出总额减退款总额与摘要一致。首版跳过退款，因此完成页必须展示退款排除原因，不能声称净支出完全等同于平台摘要。

Git 中的格式 fixture 仅保留表头、状态、类别和关系结构，身份、单号、商品、支付账户、金额与发生时间均已替换；原始账单仅在本地读取。
