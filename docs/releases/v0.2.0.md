# PocketTally v0.2.0 发行说明

v0.2.0 在 v0.1.0 的个人账本基础上，加入单所有者登录和服务端会话，重整工作台、主题与文档。账本数据库结构没有需要迁移的变更。

## 主要变化

### 认证与安全

- 新增独立的 `pocket-tally-auth.sqlite3`，保存 Argon2id 密码哈希、会话摘要和登录退避状态；账本库继续独立保存业务数据。
- 新增所有者初始化、密码重设、会话撤销和状态检查命令。重设密码会撤销现有会话。
- 新增登录页与 Nuxt 同源 API 代理。浏览器使用 HttpOnly 会话 Cookie；写请求校验来源和固定 CSRF 请求头。
- 登录失败按客户端地址持久化退避；服务端限制会话数量，并设置空闲和绝对过期时间。生产 Cookie 使用 `Secure`、`SameSite=Strict` 和 `__Host-` 前缀。

### 记账与工作台

- 使用 Nuxt UI 重构应用壳层、导航、总览、统计、交易和资源管理页面；总览与统计分析分开，交易和统计筛选可通过 URL 保留。
- 重新设计现金流趋势与空数据说明，改进首次加载、分类树、交易录入与退款流程的反馈。
- 全新账本自动预置 5 个收入分类和 12 个支出分类；已有账本不会被补种或覆盖。
- 提供八套主题配色和系统、明亮、暗色模式；改善键盘、焦点、状态播报、降低动态效果设置及三档桌面宽度下的布局。

### 文档与质量

- 将文档站迁移到 Fumadocs，按用户与开发者任务组织指南，并提供 API 参考。
- 补齐后端、前端、容器和 Chromium 浏览器质量门禁；浏览器矩阵覆盖 1280、1440、1920 三档桌面视口。

v0.1.0 的账户、交易、退款、统计和账本备份能力继续保留。

## 支持与部署边界

- 面向单个账本所有者；不提供多用户隔离、公开注册或网页密码找回。
- 公网访问必须使用 HTTPS 反向代理，设置实际的 `POCKET_TALLY_PUBLIC_ORIGIN`，将前端宿主端口只绑定到 `127.0.0.1`，并保持 `POCKET_TALLY_AUTH_ENABLED=true`。FastAPI 端口不得直接公开。
- 初始化所有者后才能登录。应用层账本备份不包含鉴权库；鉴权库需要单独的加密主机备份。
- 正式镜像支持 `linux/amd64` 和 `linux/arm64`。请固定使用 `0.2.0` 标签，不要依赖可变的 `latest`。

## 从 v0.1.0 升级

1. 停止录入，创建并校验 v0.1.0 账本备份，把副本保存到独立存储。
2. 配置 HTTPS 反向代理及实际公网 Origin；确认前端端口只绑定本机、FastAPI 无公网端口，并准备鉴权库的单独备份策略。
3. 在 `.env` 中固定 `POCKET_TALLY_IMAGE_TAG=0.2.0`、`POCKET_TALLY_AUTH_ENABLED=true`，拉取并启动新镜像。
4. 首次部署时停止前后端，以 `docker compose run --rm backend pocket-tally-auth init --username owner` 初始化所有者，再启动服务并登录。
5. 核对关键账目，创建并校验新账本备份。

详细命令见[部署与备份](../deployment.md)和[认证与会话](../authentication.md)。回退时不能只切换镜像：先停止服务，按已校验的账本备份恢复；鉴权库单独处理，不得用账本备份覆盖。

## 已知限制

- 暂无多用户所有权与隔离、数据导入和版本化数据库迁移；不支持手工 SQL 或第三方程序直接写入账本数据库。
- 浏览器自动化验收覆盖 Chromium 的三档桌面视口；Firefox、WebKit 和移动端不在本次兼容性承诺内。
