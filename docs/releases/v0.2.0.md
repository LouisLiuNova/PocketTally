# PocketTally v0.2.0 发行说明（发布前草稿）

本版在 v0.1.0 的个人账本基础上，加入单所有者登录与服务端会话。正式发布以
`v0.2.0` 标签流水线、公开镜像清单和公网 HTTPS 验收完成为准；在此之前不要将本页
理解为镜像已经发布。

## 主要变化

- 新增独立鉴权 SQLite 库、Argon2id 密码哈希、HttpOnly 会话 Cookie、登录退避与会话过期。
- 新增所有者初始化、密码重设和会话撤销命令；账本备份继续只处理账本库。
- 新增登录页面与 Nuxt 同源 API 代理，并对写请求校验 Origin 与 CSRF 请求头。
- 保留 v0.1.0 的账户、交易、退款、统计和账本备份能力；账本结构未引入需要迁移的变更。

## 部署边界

- 面向单个账本所有者，不提供多用户隔离、公开注册或网页密码找回。
- 公网部署必须使用 HTTPS 反向代理，设置实际的 `POCKET_TALLY_PUBLIC_ORIGIN`，
  将前端宿主端口只绑定到 `127.0.0.1`，且不要公开 FastAPI 端口。
- 初始化所有者后才能登录。生产环境保持 `POCKET_TALLY_AUTH_ENABLED=true`。
- 正式镜像预定支持 `linux/amd64` 与 `linux/arm64`；发布后须核对 GHCR 和 Docker Hub
  前后端四个 `0.2.0` 清单，再按[部署与备份](../deployment.md)操作。

## 从 v0.1.0 升级

1. 停止录入，创建并校验 v0.1.0 账本备份，并将副本保存到独立存储。
2. 设置 HTTPS、实际公网 Origin、只绑定本机的前端端口，并准备独立鉴权库的主机级加密备份。
3. 待发行镜像验收通过后，将镜像标签固定为 `0.2.0`，拉取并启动服务。
4. 用 `pocket-tally-auth init --username owner` 初始化所有者；登录后核对关键账目，
   再创建并校验新账本备份。

不能只靠回退镜像恢复数据。若升级后发现问题，先停止服务，再按已校验的账本备份恢复；
鉴权库单独处理，不得用账本备份覆盖。详细命令与边界见[认证与会话](../authentication.md)。

## 发布验收

- 发布准备 PR 的后端、前端、文档、容器与三视口 Chromium CI 全部通过。
- 对实际公网 HTTPS 入口完成匿名访问拒绝、登录与 Cookie、限流、密码重设和会话撤销、
  Origin/Host/转发头、防护文档端点、账本与鉴权库分离的验收。
- 标签 `v0.2.0` 指向审核后的主分支提交；标签流水线通过，四个镜像的多架构清单、
  digest、SBOM 和构建来源证明完成回读，GitHub Release 与文档站可访问。

## 已知限制

- 仍无多用户所有权与隔离、数据导入和版本化数据库迁移。
- 浏览器自动化验收覆盖 Chromium 的 1280、1440、1920 三档桌面视口；
  Firefox、WebKit 和移动端不在本次兼容性承诺内。
