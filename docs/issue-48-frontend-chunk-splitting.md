# 前端生产构建 chunk 拆分

本页记录 Issue #48 的生产构建拆分边界和可重复测量结果。目标是让首屏只携带工作台壳层和当前路由所需代码，把用户明确触发后才需要的交互层延后加载；构建工具保留默认的大 chunk 警告，避免用阈值配置掩盖产物膨胀。

## 拆分策略

Nuxt 页面继续使用文件路由和默认的路由级 code splitting。`frontend/app/app.vue` 中按需打开的两个全局表单交互层拆分；详情抽屉作为共享状态壳保留稳定挂载：

| 交互层 | 处理方式 | 原因 |
| --- | --- | --- |
| `TransactionDetailDrawer` | 保持全局壳稳定挂载，选中交易后显示内容 | 详情抽屉与编辑、退款、作废等状态切换共享选中交易；保持挂载可以避免异步组件在保存后丢失详情状态。 |
| `LazyTransactionEditor` | 点击“记一笔”、编辑或退款后 | 表单只在打开交易编辑弹窗时需要。 |
| `LazyResourceEditor` | 新建或编辑账户、分类、标签后 | 资源表单只在打开资源编辑弹窗时需要。 |

这里对两个编辑器使用 Nuxt 的 `Lazy` 组件前缀，而不是手写异步组件注册或手动 `manualChunks`。编辑器已有 `v-if` 条件，只有打开对应弹窗时才需要加载；详情抽屉保留在全局壳中以维护状态连续性。导航、数据契约和弹窗事件不变。

## 体积结果

在 2026-09-14、Bun 1.3.13、Nuxt 4.5.2、Vite 8.2.2 环境中，于 `frontend` 目录执行 `bun run build`，得到以下未压缩 client 产物结果：

| 指标 | 拆分前 | 拆分后 | 变化 |
| --- | ---: | ---: | ---: |
| 最大 client JS chunk | 449.23 kB | 346.37 kB | -102.86 kB（约 -22.9%） |
| client CSS 入口 | 287.36 kB | 287.36 kB | 不变 |
| 最大 client JS chunk 是否超过默认警告阈值 | 否 | 否 | 默认阈值为 500 kB |

拆分后的两个按需交互 chunk 约为：交易编辑器 15.3 kB、资源编辑器 17.5 kB。构建输出中的文件名带 hash，后续审计应比较体积与模块边界，不应依赖具体 hash 文件名。

## 回归检查

生产构建必须继续使用默认的 500 kB client chunk 警告阈值，并检查输出中没有大 chunk 警告：

```bash
cd frontend
bun run build
```

代码变更还应执行：

```bash
bun run typecheck
bun run test
```

涉及页面或交互的验收需要继续覆盖六个业务路由，以及[通用前端测试方案与指示](frontend-testing-plan.md)规定的 Chromium 完整矩阵。该拆分不改变账本业务语义、API 契约或数据库基线。
