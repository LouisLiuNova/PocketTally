# 十万笔统计性能验收

Issue #16 使用独立临时 SQLite 账本验证统计查询不会展开随交易数增长的 SQL
参数，并把正确性回归与机器相关的性能门禁分开执行。

## 数据集

- 100,000 笔有效原支出，分布在两个信用账户、一个父分类与一个子分类中；
- 两个 Tag，其中部分交易同时关联两个 Tag；
- 说明字段同时包含普通文本和用于组合筛选的目标文本；
- 100 笔有效退款和 100 笔作废退款，每笔退款 20 分，原支出 100 分；
- 所有数据写入独立临时数据库，不读取或修改默认个人账本。

默认测试执行一次完整正确性回归，并监听统计期间的 SQL 参数数量。消费下钻只会为
当前页的 Tag 关系使用至多 `pageSize`（当前上限 100）个参数；退款和 Tag 聚合本身的
参数数量不随账本规模增长。

## 测量方法

独立性能门禁对交易分页和七个统计/下钻接口逐个执行：

1. 每个接口先发送一次不计时的预热请求；
2. 随后连续测量 20 次完整 ASGI HTTP 请求；
3. 使用 `time.perf_counter_ns()` 记录包含路由、SQLAlchemy、SQLite、响应模型校验和
   JSON 序列化的端到端耗时；
4. 将样本升序排列，按 nearest-rank 的第 `ceil(0.95 × 20)` 个样本计算 p95；
5. 任一接口 p95 超过 1 秒即令命令失败。

运行命令：

```bash
cd backend
uv run pytest -q -s benchmarks/test_statistics_performance.py
```

## 2026-09-09 验收结果

环境：Apple M4、16 GiB 内存、macOS 26.6.2（Darwin 25.6.0，arm64）、Python
3.14.7、SQLite 3.53.4。以下单位均为秒。

| 接口 | 样本数 | min | median | p95 | max |
| --- | ---: | ---: | ---: | ---: | ---: |
| transactions | 20 | 0.087688 | 0.089367 | 0.096368 | 0.110783 |
| overview | 20 | 0.654184 | 0.679822 | 0.693781 | 0.722024 |
| cash-flow | 20 | 0.282833 | 0.310932 | 0.323493 | 0.332657 |
| expenses | 20 | 0.423588 | 0.442381 | 0.474028 | 0.480404 |
| categories | 20 | 0.524351 | 0.552589 | 0.563781 | 0.564556 |
| tags | 20 | 0.229451 | 0.230441 | 0.231833 | 0.232076 |
| calendar | 20 | 0.250584 | 0.270646 | 0.287889 | 0.290569 |
| expense-transactions | 20 | 0.105021 | 0.107931 | 0.109504 | 0.110203 |

八个接口均返回 `200`，最高 p95 为 overview 的 0.693781 秒，低于 1 秒门槛。
性能数字只代表上述环境；其他机器必须运行同一命令产生自己的验收记录。
